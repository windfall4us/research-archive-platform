# 资讯研究档案库 v2.2.1 观察期说明

> 运行阶段定义文档：本文件说明观察期的目的、范围、冻结项与退出条件。

## 一、定位

**v2.2.1 不是新功能版本，而是运行阶段定义。**

系统已形成完整闭环：

```
Telegram/资讯源 → 分类 → 事件 → 来源可信 → 传播链 → Momentum
→ 股票映射 → 事件催化 → 十大模型 → Research Score → Research Summary
→ Hermes 每日简报 → T+验证反馈
```

当前最有价值的资产是**真实样本数据**，而非代码。

## 二、观察目标（2-4 周验证三个问题）

### ① Research Score 是否有效
| RS 分层 | 样本数 | T+1 | T+3 | T+5 | 命中率 |
|---|---|---|---|---|---|
| 90+ |  |  |  |  |  |
| 80-89 |  |  |  |  |  |
| 70-79 |  |  |  |  |  |
| 60-69 |  |  |  |  |  |
| <60 |  |  |  |  |  |

重点：高 RS 是否**长期**优于低 RS（不是单只股票）。

### ② 哪个因子贡献最大
当前专家规则：事件 30% / 十模型 35% / 技术 20% / 资金 15%
数据验证后可能发现：事件实际贡献 45%（应提高）或模型胜率最高（应提高）——这是 v2.3 的基础。

### ③ Research Summary 是否减少人工时间
- 以前：看 Telegram 2h + 整理 1h
- 现在：看驾驶舱 15min + 查看重点 30min
- 目标：人工研究时间下降 ≥50%

## 三、冻结项（保持参数稳定，数据可比较）

| 冻结项 | 说明 |
|---|---|
| Event Momentum | v1.7 六维加权不动 |
| Research Score 权重 | 事件30/模型35/技术20/资金15 不动 |
| 十大模型评分 | 不动 |
| 交易状态机 | WATCH→TRIAL→ADD_1→ADD_2→HOLD 保持人工确认 |
| 分类/事件/来源规则 | 不动 |

**原因**：若今天改参数，未来无法判断「结果变好是因为数据还是因为参数变了」。

## 四、观察期允许做的事

- ✅ 简报体验优化（昨日变化 / 持仓关联）
- ✅ 查看验证统计 / RS 分层有效性
- ✅ 收集人工反馈
- ✅ 数据异常修复（bug 修复）

## 五、退出条件 → v2.3

- 收集 **200+ 真实验证样本**
- 覆盖多市场环境、多行业分布
- 数据满足后进入 **v2.3 Research Feedback Optimization**：
  - RS 权重优化
  - Momentum 参数优化
  - 事件权重校准
  - 十大模型有效性分析

## 六、安全边界（贯穿始终）
