# 资讯研究档案库 — 数据清洗阶段说明

> 保存日期：2026-08-12（基于 VPS2 实际运行的 v2.2.1 系统核实）
> 关联文档：`资讯研究档案库-数据流设计图.md`

## 数据清洗在哪一阶段？

**阶段 1：采集与入库（`archive_ingest_v2.py`）内**，作为「入库 + 归一化」的一部分。不是独立步骤，而是**入库时同步完成**。

## 具体拆分

```
数据源（vip1_cache.json）
   │
   ▼
① raw_messages（原始层）—— 原样入库，只做增量去重（chat_id+message_id 唯一，永不覆盖）
   │
   ▼
② 清洗（ingest 内同步执行，UPSERT 到 normalized_messages）：
   ├─ clean_text()        → 去除多余空白/换行（\s+ → 空格）
   ├─ content_hash()      → MD5 归一化哈希（去重依据）
   ├─ extract_institution() → 机构识别（【】内机构名 / 31家机构词典匹配）
   ├─ extract_stocks()    → 股票代码提取（ths://链接 / 6位数字，去重取前10）
   └─ extract_industries() → 行业识别（13大行业关键词词典）
   │
   ▼
normalized_messages（归一化层）—— 标题截取80字 + 机构/股票/行业标签
```

## 关键设计（清洗的特点）

| 特性 | 说明 |
|---|---|
| **原始层永不覆盖** | `raw_messages` 增量追加，保留证据 |
| **归一化层可重算** | `normalized_messages` 用 INSERT OR REPLACE（UPSERT），清洗规则升级后可整表重跑 |
| **清洗与入库同阶段** | 不是独立脚本——ingest 读一条消息 → 写 raw → 同步清洗 → 写 normalized，一气呵成 |
| **词典驱动** | 机构 31 家、行业 13 类关键词表；后续扩展只需改常量 |
| **LLM 不参与此阶段** | 此阶段是**规则清洗**（正则+词典）；LLM/Vision 提取在更后面的阶段（分类/事件层） |

## 完整闭环中的位置

```
采集 → 增量同步 → [清洗 ← 本阶段] → 分类 → 机构标准化
                  （ingest_v2 入库时同步完成）
       → 文本/图片归并 → LLM观点提取 → 版本管理 → 个股验证 → Web检索与复盘
```

**一句话**：清洗不在独立阶段，而是**阶段 1「入库+归一化」脚本（ingest_v2）内部同步执行**，用正则+词典完成文本清理、机构/股票/行业提取，之后才进入阶段 2 分类（classify_v14）。
