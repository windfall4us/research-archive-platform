## 一、系统概述

**定位**：从 Telegram 五源资讯自动构建「事件驱动型 A 股研究知识图谱平台」。系统完成从信息采集 → 事件理解 → 影响分析 → 股票关联 → 行业实体 → 研究图谱 → 模型验证 → 研究排序 → 人工决策的完整闭环。

**核心能力**：
- 资讯自动分类归档（8 主类型互斥）
- 研究对象归并（research_document 多来源聚合）
- 行业实体化（industry_entity 三级树）
- 研究图谱（5 实体统一关联：document/industry/event/stock/institution）
- 事件热度（Momentum）实时监测
- 事件→个股映射 + 持仓联动
- 十大模型融合的 Research Score 研究排序
- Graph Score / 中心度 / 可信度辅助指标（不进 RS）
- T+1/T+3/T+5 研究后验验证 + 每日快照
- Observation Mode 观察仪表盘（v2.4 调参历史数据）

**部署位置**：
- 副 VPS `173.249.203.149`（reports.wmsora.vip / vip2.wmsora.vip）
- 数据库 `/root/workspace/research_archive.db`
- API 服务 `archive_server.py`（:8095，nginx `/archive/` 转发）
- 前端 `/opt/watchlist-stock-analysis`（:3100，自选研判台内嵌）

## 六、事件系统

### 语义事件聚类（v1.5）
- 实体同义归一（SK海力士/海力士/SK Hynix → 海力士）
- 跨日期归并（相邻 ≤2 天合并，cluster_confidence 0.9→0.7）
- 汇总类消息不创建事件

### 传播链（v1.6.1）
```
时间轴展示：首发 → 机构确认 → 市场扩散 → A股映射
指标：first_at / inst_first_at / lead_minutes（机构领先）/ msg_rate（传播速率）
```

### 事件热度 Momentum（v1.7）
六维加权（每小时桶）：
```
新增消息速度 25% + 新增独立来源 20% + 新增机构 20%
+ 新增股票映射 15% + 机构响应速度 10% + 持续时间衰减 10%
```

### 事件状态机
```
emerging（新出现）→ heating（升温中）→ stable（持续）
→ fading（降温）→ closed（已结束）
```

### 事件触发点
`FIRST_INSTITUTION`（机构首次确认）/ `STOCK_EXPANSION`（股票映射扩展）/ `CONSENSUS_BUILD`（机构共识形成）/ `HEAT_BREAKOUT`（热度突破）

## 八、研究队列

### 底层（v1.8，事件×股票 50 行）
`event_watch_pool` 状态机：
```
EVENT_FOUND → RESEARCH → WATCH → MODEL_CHECK → TRIAL_READY
```

### watchpool 五条规则（永久规范，2026-08-13）
1. **热度双门槛**：新事件（trigger_at≤48h）用当前 momentum≥60；老事件用 momentum_peak≥60 且 status≠fading
2. **机构确认**：inst≥1 或 FIRST_INSTITUTION
3. **排除风险/竞争影响**
4. **排除 ST/退市/空头规避**
5. **队列上限 50**（模型分优先，DELETE 挤出）

⚠️ 时区陷阱：VPS2 系统 MST(UTC-7) 但消息时间 CST(UTC+8)，age/idle 判定必须 `datetime.now(ZoneInfo("Asia/Shanghai")).replace(tzinfo=None)`；判新旧用 trigger_at 不用 last_msg_date。

### v2.2.2 股票级聚合（冻结 Schema）
- 后端 `/api/watchpool` 按 stock_code 聚合（底层不删数据）：state=最高优先级、model_score=max、model_detail=最高分条目（⚠️ 初始化必须解析 model_detail）、rs=最新、events=事件列表（momentum 降序）、max_momentum
- 50 事件行 → 34 股票（MODEL_CHECK 13 / RESEARCH 21），每股票含 RS/模型/事件列表

## 九、Research Score 评分体系

### 四维加权（100 分制，v1.9.1 冻结）
```
Research Score = 事件强度30 + 十大模型35 + 技术状态20 + 资金状态15
```

| 维度 | 分值 | 构成 |
|---|---|---|
| 事件强度 | 30 | 事件评分10 + Momentum8 + 机构确认7 + 关联强度5 |
| 十大模型 | 35 | 命中数×5(≤25) + 强模型加成8 + 完整度5 |
| 技术状态 | 20 | 趋势8 + 均线5 + 乖离4 + 位置3 |
| 资金状态 | 15 | 当日强度5 + 市场关注5 + 量能3 |

### 状态映射
`90-100 重点研究 / 80-89 优先跟踪 / 70-79 观察 / 60-69 普通 / <60 忽略`

### 研究状态（research_state，非交易状态）
`cold（冷启动）→ warming（升温）→ focused（聚焦）→ confirmed（确认）→ fading（降温）`

### 解释层
每次评分自动生成：贡献项（+8 事件评分86 / +25 命中5项模型条件）+ 扣分项 + 缺失条件

### 历史演化（v1.9.1）
- 每日快照（按天保留，历史可回溯）
- `score_change` / `change_reason` 自动生成
- 趋势迷你曲线（7 日）

## 十二、图谱统计优化（v2.3.4）

### ① Industry Contribution Score（行业热度去重）
一级行业贡献拆分 = 子行业 `文档×2+事件` 加权占比（避免「AI产业链100+子行业100」重复观感）
```
AI产业链：AI算力 27% / 光模块 13% / AI芯片 13% / PCB 12% / 电源 11%
```

### ② Graph Centrality（股票研究中心度）
```
中心度 = 事件30% + 机构25% + 研究对象20% + 行业核心15% + 传播10%（各因子 cap 归一）
例：中际旭创 45（+30 12事件 +15 24行业）
```

### ③ 机构研究雷达
机构经 confirmed_by 事件 → 行业分布（判断「哪些机构提前覆盖主题」）
```
天风证券：AI算力 11% / 材料 10% / 半导体 8% / PCB 7%
```

### ④ Research Confidence（研究对象可信度）
```
可信度 = 质量50% + 机构×15 + 传播×8 + 事件×5 + 股票×3
区分：质量（文档本身）vs 可信（市场认可）
```

### ⑤ GS 时间趋势
行业 → 关联事件 → event_momentum 历史桶按天聚合，`_trend_dir`（近3天 vs 前3天 ±15% → ↑/↓/→）

## 十八、安全边界

**系统自动化的边界**（贯穿所有模块）：
```
✅ 自动发现   ✅ 自动分析   ✅ 自动排序   ✅ 自动统计
❌ 自动买入   ❌ 自动改持仓  ❌ 自动交易建议
```

- 研究队列/Research Score/Graph Score 均为「研究辅助」，输出「重点研究/观察」而非「买入」
- 交易状态机 `WATCH→TRIAL→ADD_1→ADD_2→HOLD` 始终保持人工确认
- 研究系统与交易系统隔离（研究 → 人工判断 → 交易）
- 所有文案带「研究辅助 · 非投资建议」后缀
- Observation Mode 冻结：不改 RS/Momentum/十模型/状态机/验证口径

### 服务管理
```bash
# API 服务
# ⚠️ 重启安全法：pkill -f 会匹配 bash 自身致自杀（cmdline 含该串）
kill -9 $(ss -tlnp | grep ':8095' | grep -oP 'pid=\K[0-9]+' | head -1)
sleep 2
nohup python3 /root/scripts/archive_server.py > /var/log/archive-server.log 2>&1 &

# 前端（watchlist）
systemctl restart watchlist-stock-analysis
```

### 前端修改后构建
```bash
cd /opt/watchlist-stock-analysis
rm -rf .vinext          # 强制重建（必须）
npm run build
systemctl restart watchlist-stock-analysis
```

### 数据库备份
- 全量备份 `/root/workspace/research_archive.db`
- 脚本备份 `/root/scripts/archive_*.py`（每版本 `.bak_YYYYMMDD_*`）
- 前端资产 `/home/windfall/workspace/archive_module/`（本地）

### 常见故障
| 症状 | 处理 |
|---|---|
| API 8095 无响应 | 端口 PID 杀法重启（勿 pkill -f / 勿 nohup 重复占端口） |
| 改了代码不生效 | 检查是否旧进程残留（ss -tlnp 看 PID，kill -9 端口 PID） |
| 数据不更新 | 检查 crontab 全链路是否有脚本失败（`&&` 链任一失败即断） |
| 前端 404/构建失败 | `rm -rf .vinext` 后重新 build |
| 事件/文档 ID 漂移 | cron 重建自增 ID——图谱/回填必须随链重建或同日匹配 |
