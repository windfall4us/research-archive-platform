# 数据加工管线与阅读规范

> 本文档提供档案库的**操作视图**与**阅读规范**，与 `数据流设计图.md` 的**系统架构视图**互补。
> 二者描述同一系统、不同粒度，不互相替代。

---

## 一、视图关系

| 视图 | 数量 | 描述 | 面向 |
|---|---|---|---|
| 系统架构视图 | **8 阶段** | 数据从进入到页面展示的完整架构 | 架构/运维 |
| 数据处理视图 | **7 阶段** | 单条资讯如何变成一条研究结果 | 操作/分析 |

> 不再使用「6 阶段」说法。8 阶段与 7 阶段是同一系统的两个正交视角，口径各归其位。

---

## 二、系统架构视图（8 阶段 · 保留）

详见 `数据流设计图.md`。概括如下，**不修改**：

```
采集 → 分类 → 归并 → 事件 → 动量/候选 → 评分/验证 → 服务层 → 展示层
```

---

## 三、数据处理视图（7 阶段 · 新增）

描述**单条资讯如何变成研究结果**的加工管线：

```
ingest      采集
→ normalize 清洗归一化
→ classify  分类（research/announcement/market/news/image…）
→ events    事件语义层（归并成事件聚类）
→ document  研报归并（去重成研究文档）
→ score     研究评分与验证
→ observation 观察（Observation Lock 运行阶段）
```

- 阶段 3（classify）→ 5（document）为「消息 → 文档」的去重归并过程，解释了「研究类消息数 ≠ 正式研究文档数」。
- 阶段 7（observation）为当前运行阶段（v2.3.4e，观察期，参数冻结）。

---

## 四、每日阅读优先级（操作规范）

按信息价值从高到低，**每天按以下顺序阅读**：

```
重点事件
→ 重点研究股票
→ 当前研究文档
→ 今日研究类消息
→ 今日新增待复核
```

不放入数据架构编号，作为独立操作规范执行。
