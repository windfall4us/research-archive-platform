## A. 持有句中的条件减/加被 HOLD 吞掉
- 来源: P1 [7] 赤峰黄金 / [59] 西点药业 / [100] 屹唐股份
- 现象: "收回5日均线持股，收不回减持，等13日均线再考虑回补" → parser 只出 HOLD，
  "收不回减持"(REDUCE) 与 "回补"(ADD) 条件动作丢失
- 要求: 支持主状态(HOLD/POSITION_STATE) 与条件事件并存：
  `HOLD + REDUCE(CONDITIONAL) + ADD(CONDITIONAL)`；"涨多减/5日线之上加/破13日线减出" 同理
- 影响动作: HOLD 分句内仍需扫描 减/加/出/回补 等条件动作词

## B. 条件卖出触发词需前置识别（不能默认 EXECUTED）
- 来源: P1 [74] 协鑫能科 "冲涨停出局"
- 现象: "冲涨停出局/接回" → parser 标 SELL/EXECUTED；"冲涨停" 是触发条件而非已执行
- 要求: 前置识别条件卖出触发词 → CONDITIONAL：
  `冲涨停出 / 破位出 / 到XX价卖 / 跌破XX减仓 / 冲高卖`
- 注意: 与协议 6 兼容（"适度减仓止盈"无触发词 → EXECUTED）

## C. 价格区间 + 仓位配置 = 计划建仓
- 来源: P1 [91] 德明利 "参考区间410-450，仓位1成"
- 现象: parser 无动作动词 → WATCH；应识别为 BUY/INTENDED
- 要求: 识别 "参考区间/配置/仓位建议/计划" 语义 + 数字区间/仓位 → BUY/INTENDED
- 前提（用户补充）: 必须有明显 "配置/参考区间/仓位建议/计划" 语义，避免任何数字区间+仓位都生成 BUY

## D. "今日XX为主" = 操作倾向（INTENDED），非 EXECUTED
- 来源: P1 [29] 宇树 "操作谨慎，今日兑现为主"
- 现象: parser 判 SELL/EXECUTED/TODAY
- 要求: 协议 10 —— "今日兑现为主/今天减仓为主/以卖为主" = 操作倾向 → INTENDED；
  仅 "已卖/已出/已兑现/减了" 等完成态词才 EXECUTED
- 触发词: `为主 / 倾向 / 为主基调`

## E. 推荐 ≠ 买入（协议 9）
- 来源: P1 [90] 天孚通信 "核心推荐标的"
- 现象: "核心推荐标的" 易被当作 BUY
- 要求: 协议 9 —— "推荐/核心推荐/看好/重点关注" 默认不是 BUY，
  归 WATCH/INTENDED 或 recommendation-only
- 影响: 防止 "重点推荐/核心标的/看好" 污染 Action Flow（虚假净买入信号）

## 待仲裁发现项（P2/P3/P5/P6 已确认）
- F. [9] 药明康德 "之前减仓的可以继续跑" —— 双事件：REDUCE/EXECUTED/PAST（历史事实）+ HOLD/INTENDED/TODAY（剩余仓位继续持有建议）；"可以继续跑"=许可非条件
- G. [73] 中恒电气 "圈友周三已加仓" —— 过去时间词(周三) → ADD/EXECUTED/PAST 未识别
- H. **[5][73] 条件/持有子句干扰主动作 temporal → 升级为协议11「动作级 Temporal/Status 隔离」**（每个动作独立 status+temporal，条件子句不覆盖前序已完成动作）
- I. **[69] 长川科技 "打底仓（盘中不追高）" → 升级为协议12「时段词≠执行态」**（盘中/早盘/尾盘只辅助 temporal，不能单独升 EXECUTED；需明确完成态证据）
- J. **[94][95] "止盈离场/回本离场" → 升级为协议13「仓位动作程度分级」**：清仓/全走→CLEAR；离场/出局/卖出→SELL；部分止盈/减仓→REDUCE；止盈是原因不是动作
- K. **姿态句识别**（[15][31][33][35]）：明确关注/观察/回避/相信/期待等、无真实交易动作 → 归 WATCH/stance，不得生成 BUY/SELL
- L. **"拿筹码"上下文解析**（[28] 华勤）：提前拿筹码/准备拿筹码→BUY；已经拿了筹码→BUY/EXECUTED；拿着筹码/手里有筹码→HOLD
- M. **"小仓位博弈"**（[76] 兖矿）：默认动作族=TRIAL；若存在"突破后/回踩后"等条件 → status/temporal=CONDITIONAL
- N. **Logic 可提供完成态证据**（[75] 有研硅 "只回了"）：只能补强结构化动作，不允许 logic 中无关词覆盖主 action
- O. **未来窗口词**（[10] 融捷）：明日/下周/月内/月底等可贡献 FUTURE_PLAN，但必须判断它修饰"动作时间"还是"持有周期/目标期限"
- P. **WATCH stance 扩展点**（[33] 回避）：未来 WATCH 可能需要 stance 子字段 FOLLOW/AVOID/WAIT/POSITIVE/NEGATIVE；否则"重点关注"与"建议回避"都变 WATCH 会丢方向信息；Phase 0B 不扩 Action 枚举，先保留扩展点
